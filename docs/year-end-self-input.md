# Year-End Self Input

## Purpose and workflow

The Share your progress navigation contains **Year-End Self Input**, at `/self-input`. This feature creates an editable first-person narrative from collected accomplishments, rather than the existing Reports template's item-by-item Word listing. Existing reports and Resume Builder are unchanged.

1. Choose a calendar/fiscal reporting year using Settings → Reporting Year, or exact custom dates. Previous years remain selectable after rollover. The default is the current organization reporting period; dates are always displayed before source selection.
2. Review sources. Completed, approved work in the period starts selected, including archived work. Unapproved entries, unfinished notes, undated entries, and work spanning the period need individual confirmation. Confirming does not change accomplishment status or approval. Trash and report-excluded entries cannot be selected.
3. Save an evidence snapshot and inspect the selected records and extracted attachment text. TXT/Markdown/CSV (UTF-8), DOCX (including tables), ODT and text-layer PDF are supported. No external evidence links are fetched. Unavailable formats, file/hash problems, size limits, missing PDF readers and unreadable text are reported. Missing or partial evidence requires an explicit acknowledgment before generation. Embedded image contents are not OCR'd.
4. Choose a configured local/private-network Ollama-compatible provider. If unavailable, the page links to Settings → AI Providers. There is no external-provider fallback.
5. Generate an initial draft. Text is ready to edit, and a separate local AI editorial pass suggests which sections belong together, with reasons. Its selection sets the initial checkboxes. Every later generation or section rewrite refreshes the recommendation without overriding user choices; **Use AI's selection** applies those checkbox choices explicitly. **Suggest section selection** reviews existing wording without rewriting it. The review considers pending rewrites with locked paragraphs retained, protects nonempty employer-question sections, and excludes empty sections. Invalid or failed recommendations preserve the generated text and existing choices. Changes to wording or writing preferences make recommendations stale until refreshed. Older saved initial proposals also open as editable sections. Later AI rewrites appear beside existing wording and require explicit acceptance; accept desired rewrites and dismiss remaining proposals before another generation.
6. Edit draft paragraphs, lock paragraphs against AI replacement, add manual paragraphs, and answer section-specific questions. Every writing or rewriting run makes a fresh local AI question pass for each generated section, using its latest wording, evidence and existing answers. Questions appear above **Your answers or additional context**; pending rewrites show questions about that proposed wording. The separate question button refreshes questions without rewriting text. Empty results and provider failures are explained explicitly; a question failure does not discard successful writing. Rewrite one section with answers, or request shorter, clearer or more natural wording. Questions and answers are stored separately from submission paragraphs and excluded from exports. Paragraph locks protect wording against AI replacement; they do not control section inclusion.
7. **Generate all sections** asks the configured local Ollama provider to prepare every section up front, even unchecked sections. The app makes smaller sequential requests internally, then shows the writing for comparison and selection. **Refresh all sections** proposes new wording without replacing existing text automatically. For partial drafts, **Write missing sections** fills only empty sections, preserving existing text, paragraph locks, questions and checkbox choices. The header shows how many sections have draft text. **Include this section** only changes the combined draft selection; it never starts an AI request. Existing text and word/character counts update immediately. **Write and include this section** remains available as an explicit individual action. Missing evidence produces questions instead of invented text. Unchecking preserves text and answers; Save draft persists choices. Copy and Word, ODT and plain-text exports contain only included sections. Confirm review to save an immutable approved version. New drafts and later edits never modify old approved versions.

The **Your self inputs** list has individual Delete controls, unchecked selection boxes, Select all, and a **Delete selected (count)** button. Creation timestamps distinguish repeated titles. You can select up to 200 assessments per batch. Delete opens a confirmation page listing the selected assessments and their approved-version counts; confirming permanently removes those assessments and their approved versions, with audit events. Original accomplishments, uploaded supporting documents, other assessments and previously downloaded exports are kept. Assessments are not recoverable through Trash. Authentication, CSRF validation and revision checks protect deletion. Bulk deletion is atomic: if any selected assessment changed or disappeared, none are deleted. Selection and confirmation also work without JavaScript; Select all and live counts require JavaScript.

## Voice, structure and evidence

An optional **Goals or performance expectations for this review period** field is available during setup and under Writing preferences on existing drafts. Paste one or several goals (up to 12,000 characters). They persist with draft preferences and approved versions, guide relevance and gap questions, and remain separate from optional next-year goals. Goals are not factual evidence: target numbers cannot validate claimed achievements. Meaningful work outside the goals remains eligible. Changing goals does not overwrite existing paragraphs; generate and review fresh proposals to use them. Older drafts without the field behave as before. No additional migration is required for this field.

Default sections cover overall contribution, major results, collaboration, problem-solving and professional development. Optional employer questions replace these headings. Challenges/lessons and next-year goals are optional; goals require the user's confirmed answer. The optional writing sample guides voice only, not current-year facts. Narrative, bullets and mixed styles have approximate word targets; a character limit is optional and excess text requires explicit approval rather than silent truncation.

Sources include original notes, Action/Metric/Impact, supporting narrative, project descriptions, skills, competencies, technologies, tags, categories, systems, keywords, references and locally extracted attachment text. Dates, completion state and explicit confirmations remain attached to the evidence. Older unfinished notes may be offered for review because ongoing work can contribute this year; this is never assumed without confirmation. For work completed outside the period but spanning it, only the contribution during the selected dates may be described.

Evidence is processed in bounded batches. Every character of every selected snapshot is accounted for in its batch; large records are labeled as parts. The model must return an entry for every part with exact supporting excerpts. These excerpts are verified against the submitted source text before synthesis. Unsupported numeric claims, unknown source IDs, citations without evidence, malformed output and bracketed placeholders are rejected. Summarization is selective: these checks do not establish semantic truth or guarantee that the model chose every important fact. Users must review their actual contribution, wording and completeness.

Source links on paragraphs retain the evidence revision used for generation. Coverage shows which sources appear in current draft sections and any model explanation for omissions. Manual wording edits do not automatically verify or change their source citations. The model is instructed to combine related contributions, preserve routine responsibilities and qualitative impact, avoid double counting, and distinguish individual contribution from team results.

Refreshing the source selection saves new evidence snapshots, clears cached AI evidence extraction, and retains paragraphs, answers and historical evidence. Fresh AI proposals still require explicit application. An approval rechecks selected sources; changed evidence needs review and explicit acknowledgment. Unavailable/report-excluded/deleted selected records must first be removed through source review. Previous approved versions remain historical snapshots even if the underlying records later disappear.

## Storage, limits and operations

Migration `0010_self_inputs`, following `0009_entry_dates`, adds the `self_inputs` table. The table contains drafts, source/evidence history, preferences, proposals, optimistic revisions and approved versions. No original accomplishment or attachment is rewritten. Source snapshots may contain sensitive supporting text and writing samples; they are persisted locally along with the draft and therefore appear in database backups. Exports are built on demand, require authentication, and contain only approved narrative sections, title and period—not answers, prompts or internal evidence links. Plain text uses exactly the current section/text composition shown in the preview.

Source attachment extraction is bounded at 25 MB per file, 50 MB expanded document packages, 100 PDF pages, and 100,000 extracted characters per document. Unsupported/oversized content is explicitly marked unavailable, never silently truncated into evidence. Final synthesis is capped at 110,000 prompt characters and the configured AI response size. Excessively large selections fail with a clear request to narrow scope. Batch inference is sequential and may take several minutes; the submitted draft is saved before provider I/O. A failed request preserves it. Model-quality issues can still require retrying or choosing another configured local model.

All form mutations use authentication, CSRF and optimistic revisions. Concurrent tabs or inference finishing after a newer save cannot overwrite that newer revision. Rendering a GET page makes no AI calls. Approved versions and source history are not sent to Git Sync. Restoring a database snapshot restores this feature's saved narratives and evidence; full backups additionally retain original supporting files.

## Validation handoff

Focused service and route tests, Ruff, JavaScript syntax and Git whitespace checks have been run during implementation. Isolated browser checks cover section selection, live preview, empty-section writing, questions, keyboard interaction, responsive overflow and bulk deletion. Live Ollama checks use read-only copies of saved evidence; they do not approve or overwrite the user's saved assessment. This is not a claim that every manual acceptance item below has been completed.

Self-input writing uses one section per model request, with a share of the overall word target, a paragraph/bullet count based on that target, and all selected evidence. Prior proposed sections provide context to reduce repeated wording without preventing the same work from supporting another section. AI calls use [Ollama's streamed NDJSON responses](https://docs.ollama.com/api/streaming). The provider timeout detects inactivity between network reads, allowing longer generations to continue while tokens arrive. Each individual model call also has a total deadline of 300 seconds or the configured provider timeout, whichever is greater. Response size limits still apply. Only a complete, valid response is accepted; interrupted output is never applied as a draft. Timeout, connection and HTTP errors identify the failure without displaying provider credentials or response content.

Run with an isolated test environment (the existing test fixtures set one):

```powershell
$env:PYTHONPATH = 'backend'
.\.venv\Scripts\python.exe -m pytest tests/test_self_input.py tests/test_self_input_routes.py
```

Then run the existing regression suite using `scripts/test.ps1`. Restart via the normal `scripts/run-prod.ps1`; it applies pending migrations before starting the server. Do not run a second server on the same port.

Manual acceptance checks:

- Calendar, fiscal and previous-year selection; exact date boundaries; archived, raw/unapproved, spanning-period, report-excluded and deleted records.
- Empty and populated inventories, confirmation failures, readable/unsupported/missing/partial attachment text, and missing `pypdf`.
- No provider, remote provider rejection, timeout, invalid JSON, incomplete evidence-part coverage, invented source quotations and unsupported numeric claims.
- First-person draft quality, meaningful recurring responsibilities, optional voice sample without imported facts, employer headings, and optional goals with/without confirmed input.
- Section questions/answers, locked paragraphs, manual edits to pending proposals, applying one section, dismissing remaining proposals, and preserving everything on failed regeneration.
- Source refresh with changed/new/removed records, accurate citation history, concurrent tabs, and explicit approval of changed evidence.
- Character limits including Unicode, clipboard fallback, mobile layout, keyboard focus and all shared light/dark themes.
- Word/ODT output content and pagination, absence of questions/internal citations, immutable approved versions, downloads without authentication, and backup/restore.
